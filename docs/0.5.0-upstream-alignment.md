# 0.5.0 上游 API 对齐记录

本轮已在 `reference_codes/qtmodel-release` 执行 `git pull --ff-only`，核对范围为
`8ae651e..0687ffe`。参考仓库保持干净，未修改上游源码。
`0687ffe` 仍标为 qtmodel 2.9.2，但与 PyPI 2.9.2 wheel 内容不同；以下能力按实际
callable 和签名判断，不根据版本字符串启用，也不在服务启动时连接桥通探测。

## 差异与处理

| 领域 | 上游变化 | Qiao-MCP 处理 |
|------|----------|---------------|
| 一般/弹性支承 | 只给附加参数时自动启用；False 清空；覆盖省略项保留；节点去重与输入校验加强 | 专用工具显式补 `extra_enabled=True`，使旧的可支持 SDK 也具有相同行为；False 不覆盖。写前签名校验，成功提交一次，提交失败明确提示可能已改模型。原生节点解析仍由 SDK 处理。 |
| 混凝土检算 | `solve_concrete_check` 移除 `show_view/modal/auto_close/sync`，后台任务显示可终止的非模态进度窗口 | 既有工具只传 `wait/poll_interval/max_wait`，无需新增窗口选项；实际协议测试覆盖先导入具名工况再求解、成功/失败/取消，无 MDB 提交。网关以安装版本的签名拒绝已移除参数。 |
| 截面纵向配筋删除 | 新增 `cdb.remove_section_reinforcement(sec_id, position)`，操作当前 CSAN 数据 | 与 B3 基础模型的 `remove_section_reinforcement_by_name` 分开；前者经网关用原检算权限且不提交 MDB，后者支持完整标识并按模型写入提交。 |
| 单元质量/刚度系数 | 新增专属 add/update/get/remove；保留通用 set/remove；组引用动态展开，重叠定义以最大编号生效 | 经网关发现真实签名并传关键字参数，兼容通用接口参数顺序变化。查询零提交；写入提交一次。保留 0、None、空列表和完整选择范围。 |
| 翼缘/有效宽度 | 新增 `set/get/remove_flange_width`、`get_flange_width_lines`、`get_effective_width_spans`、`calculate_effective_width` | 继续经网关提供；计算有效宽度会写入宽度/系数定义，属于模型写操作。I/J 端、腹板与加劲肋定义、不同系数原样传递；不当作纯只读计算。 |
| 统计 | 新增 `get_element_weight_table`、`get_load_statistics`、`get_material_statistics` | 经网关作为模型只读查询，保留原始行和扩展字段，不补造合计。单元重量、材料重量固定 N；`find_entities(by="element_weight")` 同步该单位说明。 |
| 节点与单元复合操作 | 新增 `merge_node_groups`、`merge_frame_elements`、`merge_plate_elements`、`move_nodes_by_offsets` | 经网关统一提交，不展开内部叶子命令；保留 `delete_free_nodes`、`accept_warnings`、`intersected` 及原始顺序。实际合并数量以返回值为准。 |
| 图片 | `save_png` 的路径变为可省略，绘图路径类型明确接受 None；文档澄清空路径返回纯 Base64 | 既有图片工具已使用空路径获取图片；调用参数兼容。绘图函数执行体没有变化，保留已有 MCP Image 路径和图片验证。 |
| 其他说明 | `remove_pre_stress` 按钢束名称删除荷载；单元检算信息为完整 12 项行；配筋端位置为 0/1 | 保持已有接口与网关；不把钢束名误当组名，不把计算长度 0 当作“保留”，不混用变截面插值编号与 I/J 端。 |

`MdbEffectiveWidth`、`MdbElementFactor` 已加入上游公开 facade。测试从真实 `qtmodel.mdb`
取方法，覆盖混入类的实际解析路径，而非直接调用某个源码类规避 facade。
比较时同时检查签名和去除 docstring 后的 AST 执行体；已有函数的执行体变化集中在
支承与混凝土检算，图片的大段差异主要为类型和说明。

## 本仓库验证证据

- `tests/test_support_options.py`：启用/清空/保持、原生八项参数与正负轴、旧客户端写前拒绝、提交失败。
- `tests/test_upstream_alignment.py`：47 个用例，在 PyPI 2.9.2 和 `0687ffe` 均通过。
  旧客户端没有某个端点时，验证明确拒绝且零写入；通过不表示该旧客户端具备新能力。
- `tests/fixtures/upstream_model_commands.json`：从上游系数、有效宽度、结构命令日志中抽取
  21 条相关调用；只解析 AST 字面量，未执行日志代码。3 条日志失败注释保留数量说明，
  未伪造缺失的操作。
- `tests/test_international_*.py`、`tests/test_en1991_factories.py` 和配筋/横向测试分别验证 B2–B4；
  参考仓库无需随包发布，CI 使用本仓库保存的 fixture。

完整旧版兼容矩阵和最终 wheel/stdio 结果记录在最终验收报告中。依赖仍为
`qtmodel>=2.6.3,!=2.9.0,<2.10`、`mcp[cli]>=1.29,<2`。

## 验证边界

上述测试使用真实 SDK 构造器和假 QtServer，未操作桥通活动工程，不能证明工程数值结果。
横向、配筋和三类国际活载的工程端验收仍按 [实施清单](0.5.0-plan.md) 单列。
上游未明确 BS 轴列力单位：只保留已核实的原生值，不能据离线通过推断为 N 或 kN。
