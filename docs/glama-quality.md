## 0.5.0 已准备的改进

- 596 个参数全部带 Schema 描述，151 个非图片工具带输出 Schema。
- MCP 握手返回实际包版本 0.5.0，便于辨认重新采集的目录。
- `assign_tendon_elements` 已说明它是全模型预应力单元声明、没有单根钢束选择参数，
  并给出创建钢束、声明单元、施加预应力的顺序。
- 分组增员、节点修改/改号和两种阶段视图切换已给出选择依据。
- 本轮进一步区分截面几何试算、已有截面读取和全部截面重新计算，说明写入范围及返回内容。
- 修正分组增员工具的过期指引：移除成员可直接用已有的 `remove_from_structure_group`，
  无须先转到通用网关；同时明确成员关系、组和模型实体的区别。
- 服务器 instructions 增加相近工具的选择指引；原工具名称和调用签名保留。

这些是可核对的目录和说明改进，不能换算成尚未取得的线上分数。

发布后还从 PyPI 全新安装，使用 MCP SDK 1.30.0 和 Pydantic 2.14.1 重新检查
stdio 协议。153 个工具的定义和服务器 instructions 与发布前候选完全一致；
旧快照最低分的 10 个工具都已更新说明。检查结果仍是 596 个参数说明和
151 个输出 Schema，说明本地候选的目录改进已进入真实发布包。

## 官方 TDQS 离线检查

按 [TDQS CLI 文档](https://tdqs.dev/cli) 使用 `tdqs==0.1.0`，规范版本 1.2，
对最终 wheel 导出的完整目录执行离线检查：

```bash
uvx --from tdqs==0.1.0 tdqs lint \
  --file /tmp/qiao-0.5.0-release-ready-20261012/catalog.json \
  --server-name qiao-mcp --format json \
  --output /tmp/qiao-0.5.0-release-ready-20261012/tdqs-lint.json \
  --fail-on warning
```

结果：**0 error、39 warning、2 info**，严格 warning 阈值下退出码为 **1**。
没有把该次运行报告为“全部通过”，也没有改阈值重跑来隐藏提醒。

39 条 warning 均为 `shadow-candidate`：按入参调用成本筛出的候选，尚未判断工具用途
是否真的重合。例如它把创建梁单元与显示过滤配成一组，这不能直接证明两者冗余。
按官方说明，需要后续语义评分才能确认用途冲突。两条 info 来自图片工具没有
JSON 输出 Schema，符合本项目保留 MCP Image 返回的设计。

本次只运行离线 lint，没有调用评分模型或提交 Hosted API 评分请求。
[TDQS 规范](https://tdqs.dev/)中的 A 阈值为 3.5，B 阈值为 3.0；
离线 lint 不生成这些分数。原始检查报告随本机候选包归档保存。
