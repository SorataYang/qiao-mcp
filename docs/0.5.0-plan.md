# 0.5.0 实施与验收清单

依据之前对话确认的「方案 B」，保留 B1–B4 的完整范围。上游参考仓库已执行
`git pull --ff-only`，本轮基准为 `0687ffe`（仍标为 qtmodel 2.9.2）。
按可调用方法和签名探测能力，不用版本号判断。方案 A 的 0.4.0 提交独立保留。

每个功能提交包含工具、输入/输出 Schema、Provider、权限、目录数量和必要测试。
现有工具与资源 URI 保持兼容。新功能缺 API 时在写入前失败；查询不伪造空结果。
写入只提交一次；响应丢失或提交失败时回读，不自动重放命令。仅创建本地提交。

## 离线检查

每阶段验证 FakeDb 分发、真实 SDK 到假 QtServer 的 header/payload、上游导出样例、
旧版能力缺失、权限拒绝、错误和未知写入结果、MCP 参数约束与注解。测试样例随本仓库
保存并注明来源，不依赖未跟踪的参考仓库。所有新非图片工具必须提供输出 Schema。

最终执行 ruff、mypy、离线 pytest（排除会重建活动模型的 `test_end_to_end.py`）、
构建 wheel 和 `scripts/check_mcp_package.py`。兼容矩阵覆盖 2.6.3、2.6.4、2.8.2、
2.9.1、2.9.2 和最新源码；2.6.3 缺少 `get_load_group_names` 的两个既有失败单列。
