每行均收集 2014 项；旧版缺失的快照、国际/横向活载、状态等能力按现有契约跳过。
其中 36 项新的原生实例/修订上下文测试在旧 SDK 中因接口不存在而跳过，在 2.9.3 上全部运行。
2.9.3 的专项测试另通过删除 SDK 方法、移除桌面协议标记来验证回退仍受原状态守卫约束。
每项跳过原因保存在 JSON 中，没有把跳过计入通过。

所有加载的 SDK Python 源文件均逐字节比对其对应 wheel，未修改 SDK 源码来使测试通过。
2.6.4 的包元数据版本为 2.6.4，但其 `qtmodel.__version__` 仍返回 2.6.3；
矩阵按发行包和文件校验值识别版本，不以该运行时常量代替包来源。

## 新保护的验证范围

新增 36 项测试通过原生 QtServer 传输构造请求，并在 HTTP 边界模拟响应，覆盖：

- 真实握手字段经 SDK、Provider 传到保护逻辑；权限检查与绑定使用同一份新快照。
- 两种 MCP 目录中的创建、成员写入及各次提交始终携带同一工程实例。
- 首次写入或提交时收到实例不匹配后停止，不继续后续写入或自动重放。
- 未知写入结果保留原错误说明；嵌套调用不能改绑工程，失败和取消均清理上下文。
- 后台分析工作线程继承上下文，并行异步调用之间的实例标识相互隔离。
- 网关 Undo 携带模型/历史修订号，拒绝过期、待提交、无效或不确定修订。
- 旧 SDK/桌面的既有状态检查，以及初始化、打开/保存/导入文件的原生载荷保持兼容。

这些测试证明客户端的请求、作用域与错误处理；没有替代新桌面端实际执行前的拒绝验证。
实例绑定不等于事务回滚或跨请求的审阅计划。

## 全新安装

单独创建 Python 3.11 环境，直接安装候选 wheel，让依赖按公开约束解析，没有使用项目锁文件。
实际解析到 qtmodel 2.9.3、MCP 1.30.0、Pydantic 2.14.1、NumPy 2.4.6、Pandas 3.0.6。
其两种工具目录与锁定环境的工具定义逐项相同，stdio 检查均通过。

随后仅加入 pytest 9.1.1 及其测试依赖，确认 Qiao-MCP 导入路径位于该新环境的已安装 wheel，
再运行全部离线测试：**2014 通过、0 失败、0 跳过**，耗时 48.47 秒。
锁定环境对应的完整测试耗时 60.17 秒。

所有完整回归显式排除 `tests/test_end_to_end.py`，使用 FakeDb/模拟 SDK 传输，并将
真实 `requests.sessions.Session.request` 替换为抛出连接错误的离线桩。
协议检查仅使用未开放的本地端口，核对未连接状态和非法输入，不执行有效的模型修改。
