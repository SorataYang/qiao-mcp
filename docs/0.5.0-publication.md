## 发布流程修复

首次远端构建自动安装了 uv 0.13.0，它会重排源码包内的 `pyproject.toml` 并移除注释，
触发逐字节一致性检查，因此当次没有上传。
提交 `a641154` 将 CI 和上传任务的 uv 固定为本地已验证的 **0.11.6**，
符合项目 `uv_build>=0.9.28,<0.12` 的范围。
actionlint 1.7.12 校验通过，重新构建的包与原候选逐字节一致，随后远端检查和发布成功。

## 已知限制与 Glama

发布没有改变当前桥通构建的工程实测结论：基础静力和已测 B1 通过，
Rz 返回错误、B2/B3 接口阻断仍在，B4 完整流程尚未开展。
详见[发布说明](0.5.0-release-notes.md)和[实测报告](0.5.0-live-validation.md)。

发布完成时 Glama 仍在展示旧的 0.3.1、132 工具快照及 B 3.3/5。
已由维护者请求仓库重新同步；仓库同步、容器构建和 MCP 工具采集需要分别核对。
后续评分与改进跟踪在 [Glama 记录](glama-quality.md)，发布成功本身不代表评分已更新。
