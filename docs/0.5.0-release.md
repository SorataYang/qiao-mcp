## 本地检查

在仓库根目录运行以下命令。`--tag v0.5.0` 仅验证拟用版本，不创建 Git 标签。
构建目录应为空或只包含当前版本的 wheel/sdist；报告保存在目录外。

```bash
uv sync --locked --dev
uv run --locked ruff check src/ tests/ scripts/
uv run --locked mypy src/qiao_mcp/
uv run --locked pytest tests/ --ignore=tests/test_end_to_end.py -q
uv build --out-dir /tmp/qiao-0.5.0-closeout-dist
uv run --locked python scripts/check_release.py /tmp/qiao-0.5.0-closeout-dist \
  --tag v0.5.0 --output /tmp/qiao-0.5.0-release-check.json
uv run --locked python scripts/check_mcp_package.py \
  /tmp/qiao-0.5.0-closeout-dist/qiao_mcp-0.5.0-py3-none-any.whl \
  --output /tmp/qiao-0.5.0-closeout-catalog.json
uvx twine check --strict /tmp/qiao-0.5.0-closeout-dist/*
git diff --check
```

本地 editable 分发元数据已同步为 0.5.0。运行时依赖范围未变；新增的 `packaging`
只是显式声明发布检查所需的开发依赖，锁文件中的版本未升级。

`check_release.py` 检查 `pyproject.toml`、`server.json` 顶层及 packages、`uv.lock`
本项目版本、拟用标签、两种包的元数据/依赖/Python 范围/README、源码和 wheel 入口。
它拒绝混入其他版本或多余文件的构建目录，并输出两种包的 SHA256。
35 项独立离线测试覆盖有效产物、版本漂移、过期/缺失源码、错误入口和失败时不输出版本。
最终六组矩阵各收集 1768 项：PyPI 2.9.2 和参考源码全部通过；旧版本的跳过项及
2.6.3 的两个既有失败分别记录。最终 wheel/sdist 也已通过 Twine 的严格元数据检查。

`check_mcp_package.py` 从构建 wheel 启动真实 stdio 会话，核对 0.5.0 握手、
153 工具、151 输出 Schema、596 顶层参数说明、7 资源、5 prompts 及 MCP 错误通道。
它固定访问本机未开放端口，不发现或操作真实桥通工程。

## CI 与发布触发方式

`.github/workflows/publish.yml` 复用 `ci.yml`：锁定环境、ruff、mypy、完整离线测试、
构建、版本/源码检查和 stdio 检查全部成功后，才上传供发布使用的同一份 artifact。
标签与版本不一致会失败。TestPyPI 的版本查询只有 200 表示已存在、404 表示可上传；
其他 HTTP 状态或传输失败会中止，避免把查询失败当成版本不存在。

- 推送 `develop`：检查通过后可能上传 **TestPyPI**，不是单纯备份代码。
- 推送 `v*` 标签：检查通过后进入 **PyPI** 发布 job，并受 GitHub 的 `pypi` 环境规则约束。
- 本地 commit、`uv build`、上述检查脚本均不触发远端发布。

这两个 workflow 已通过 actionlint 1.7.12 的本地静态校验；本轮没有触发远端 workflow。
