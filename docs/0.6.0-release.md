## 本地复查命令

使用 uv 0.11.6。以下命令只构建和检查，不创建标签或发布：

```bash
uv sync --locked --dev
uv run --locked ruff check src/ tests/ scripts/
uv run --locked mypy src/qiao_mcp/
uv run --locked pytest tests/ --ignore=tests/test_end_to_end.py -q
uv build --out-dir dist/release-0.6.0-20261015/packages
uv run --locked python scripts/check_release.py dist/release-0.6.0-20261015/packages --tag v0.6.0
uv run --locked python scripts/check_mcp_package.py dist/release-0.6.0-20261015/packages/qiao_mcp-0.6.0-py3-none-any.whl
uv run --locked python scripts/check_mcp_package.py dist/release-0.6.0-20261015/packages/qiao_mcp-0.6.0-py3-none-any.whl --catalog-layout flat
uvx --from 'twine==6.2.0' twine check --strict dist/release-0.6.0-20261015/packages/*
git diff --check
```

原始离线回归另使用忽略目录中的 `run_offline.py` 阻断实际 HTTP；矩阵按独立 SDK 源码路径
和独立 pytest 临时目录运行。任何包内源码或元数据变化后，应重新构建、验证并更新哈希。

## 用户执行发布

1. 审阅本地 `optimize/mcp-tools` 分支及升级说明，按自己的 PR 流程推送并合入 `main`，
   等待 CI 通过。若改用 `develop`，推送会触发 TestPyPI 上传。
2. 若实际发布日期晚于准备日期，先调整 CHANGELOG 日期。对准备发布的 `main` 内容重新
   核对版本与候选；合并带来包内变化时，重新构建并更新验证记录。
3. 在确认好的发布提交上创建并推送 `v0.6.0` 标签。`publish.yml` 会复用 CI，检查成功后
   上传同一份构建产物；在 GitHub 的 `pypi` 环境完成人工审批并确认上传任务成功。
4. 核对 PyPI 的 0.6.0 版本与实际包哈希，再创建 GitHub Release。正文已准备好：

```bash
gh release create v0.6.0 --verify-tag --title 'Qiao-MCP 0.6.0' --notes-file docs/0.6.0-release-notes.md
```

5. 在客户端核对握手版本为 0.6.0，并刷新工具目录。默认应看到 15 个领域工具，完整覆盖
   153 项操作；选择 `QIAO_MCP_CATALOG_LAYOUT=flat` 则看到原有 153 个工具名称。

本次候选未新增真实工程验收。SDK 新保护仍需要支持相应协议的桥通桌面端；已知工程限制
见发布说明，不能把版本升级或离线检查解释为 B2～B4 完整实测通过。
